Protocol Vision
Not a SaaS. A protocol.
Most quest platforms are Web2 databases wearing a Web3 badge. Web3Cash is the opposite — the blockchain is the source of truth, not a feature. Every campaign escrow is a smart contract event. Every payout is an on-chain transaction. Every user identity is cryptographically bound to a wallet. The database is a cache, not the record.
The one-sentence thesis
Web3Cash is ironSource for Web3 — a CPI/CPA network where verification happens on-chain so neither side needs to trust the other, and neither side can cheat the other.
Regular SaaS vs Web3Cash Protocol

The Three Actors in the Protocol
🏢 Projects (Advertisers)
Web3 protocols, DeFi apps, GameFi. Deposit USDC escrow. Set quest type + reward. Pay only when a verified completion fires.
👤 Users (Earners)
Crypto users with EVM wallets. Connect via SIWE, browse quests, complete verified actions, earn USDC directly to wallet.
⚙️ Web3Cash Protocol
Neutral verification layer. Verifies actions on-chain. Manages Sybil scoring + payout queue. Takes 15% margin. Cannot steal escrow.

Why Ethereum as Layer 1
Ethereum has the deepest USDC liquidity, the most on-chain history per wallet (critical for Sybil scoring), and the widest wallet support. Our Sybil engine is more accurate on Ethereum than on any younger chain precisely because wallets have years of history to score against.
Smart Contracts
Two contracts. Minimal surface. Maximum security.
Less code = less attack surface. Both contracts are under 200 lines. Third-party audit required before TVL exceeds $50K. Circuit breaker on all payout functions.
Contract 1 — Web3CashEscrow.sol
Holds project USDC. Releases payouts via EIP-712 signed messages. Refunds unused budget on campaign end. Pause function controlled by Gnosis Safe 2-of-3.
FunctionWhat it does
deposit()Project calls with campaign ID and USDC amount. transferFrom + emit CampaignFunded event
release()Backend passes EIP-712 sig. Verifies signer = OTWL key. Checks nonce. Sends USDC to user wallet
refund()Campaign end — remaining USDC returns to project wallet automatically
pause()Gnosis Safe 2-of-3 only. Stops all payouts. Emergency circuit breaker
Contract 2 — Web3CashRegistry.sol
On-chain identity registry. Binds wallet address to GitHub, Twitter, or Discord ID permanently and publicly. Read by verification engine to prevent multi-wallet Sybil attacks.
FunctionWhat it does
register()Wallet signs transaction. Links wallet ↔ social ID on-chain. Emits IdentityBound event
lookup()Read-only. Returns all social IDs bound to a wallet. Used by verification workers
isBound()Returns bool. Is this social ID already claimed by another wallet?
Smart Contract Payout Lifecycle
1
Project approves USDC → calls deposit()
ERC-20 approve on USDC contract first. Then call deposit(campaignId, amount). Contract pulls USDC via transferFrom. Emits CampaignFunded event. Alchemy webhook detects → DB campaign = FUNDED.
On Ethereum mainnet · tx hash recorded
2
User completes quest → verification passes all checks
BullMQ worker verifies the action on-chain or via API. Sybil gate, funder cluster check, velocity limit, idempotency check — all pass. Payout job queued with 30-min (or 72-hr social) hold.
BullMQ delayed job · exponential backoff retry
3
Backend signs EIP-712 payload with OTWL key
Typed data: {recipient, amount, nonce, campaignId, deadline}. Signed with the protocol's OTWL private key. Nonce is unique per payout — prevents replay attacks. Signature passed to release().
EIP-712 · replay-protected · nonce-gated
4
release() called → contract verifies → USDC sent
ecrecover(sig) must equal OTWL_KEY. Nonce must not be used. Amount must be within campaign budget. All checks pass → USDC.transfer(user, amount) → emits PayoutReleased event → Alchemy webhook → DB confirmed.
Path A — All checks pass
USDC sent to user wallet
PayoutReleased event on-chain. Tx hash stored in DB. User notified via Telegram. Payout status = CONFIRMED.
Path B — Any check fails
Revert — no funds move
InvalidSigner: ecrecover mismatch. NonceReplay: already used. BudgetExceeded: campaign depleted. No partial state.
User Journey
Wallet connects. Quest completes. USDC lands.
The user never interacts with a smart contract directly. The protocol handles all on-chain operations — but every outcome is verifiable by them on Etherscan without trusting Web3Cash.
1
Land on web3cash.io → Connect Wallet
MetaMask or WalletConnect. Sign SIWE message — EIP-4361 standard. No gas required. Cryptographic proof wallet owner initiated the session. JWT created. User record created in DB with wallet as primary key.
2 minutes · zero friction
2
Sybil Score computed — 8 signals via Alchemy
Wallet age, tx count, gas spend, DeFi interactions, token diversity, Gitcoin Passport score, social proof, funder clustering. Score 0–100 computed and cached for 7 days. Score gates quest eligibility.
Score 70+
Full quest access
All quest types available including high-value deposit quests. Fast-track verification.
Score 40–69
Starter quests only
Follow, visit, video quests. Building on-chain history raises score over time.
Score below 40
Manual review queue
4-hour human review. Not blocked permanently. Most fresh wallets pass on resubmission after first tx.
3
Link Twitter / Discord via OAuth 2.0 PKCE
User connects social. Access token stored AES-256 encrypted. Social ID written to Web3CashRegistry.sol on Ethereum — permanent public binding. One social account per wallet enforced at contract level.
Identity Registry tx on Ethereum
4
Browse Quest Feed → pick a quest
Active quests filtered by eligibility. Project verified badge shown. Reward in USDC shown upfront. Spots remaining shown. One click to start — creates PENDING completion record with UNIQUE(quest_id, user_wallet) constraint.
5
Complete the action → submit
Follow on Twitter, install dApp, make deposit, connect wallet, watch video, visit site. User submits completion. API returns 202 immediately. BullMQ verification job fires async.
Under 60 seconds for on-chain quests
6
72hr hold (social) or 30min hold (on-chain) → USDC released
Smart contract release() called. USDC arrives in user wallet on Ethereum mainnet. Tx hash sent to user via Telegram and email. User can check it on Etherscan independently — no trust in Web3Cash required.
Real USDC · Real Ethereum tx · Real wallet
7
Withdraw as crypto or convert to fiat
Min $5 withdrawal. Crypto: Circle API sends USDC to any EVM wallet in 1–3 minutes. Fiat: Transak widget (under $2K), Ramp Network ($2K–$10K), Circle Wire (over $10K). KYC required above $500 cumulative.

Name, website, Twitter, on-chain contract address. Automated checks: WHOIS age, Twitter follower count, on-chain contract existence. Results in under 5 minutes. Pre-check failure → request more info → retry in 7 days.

Growth team reviews within 24–48 hours. Approval sends dashboard access link. Rejection sends email with specific reason and 30-day cooldown. Approval also begins KYC process for entity verification.
24–48hr SLA

Entity KYC via Persona → Connect wallet → Deposit USDC
Company registration doc + director ID. 10 minutes via Persona. Once cleared: connect project wallet via SIWE. Deposit minimum $500 USDC to Web3CashEscrow.sol. Funds locked. Dashboard activates.
Min $500 USDC · Smart contract escrow · Refundable
4
Campaign wizard → Configure quests → Set audience
Choose quest types (follow, deposit, install, etc.). Set reward per completion. Set max completions. Set minimum Sybil score for audience. Preview total budget commitment. Sign escrow tx to lock USDC on Ethereum.

Quests appear in user feed. Telegram + Twitter announcements sent. Dashboard shows: live completions, wallet addresses, Sybil scores, tx hashes, spend rate, budget remaining. Export as CSV anytime.

The escrow guarantee
A project cannot rug users because funds are in a smart contract. Web3Cash cannot steal funds because only EIP-712 signed requests from the OTWL key can release them. Neither side can cheat — the contract enforces honesty.
Admin Flow
Operations dashboard — four queues, full audit trail.
Admins have four queues: project review, completion review (fraud flagged), withdrawal review (KYC gate), and fraud alerts. Every admin action is logged immutably.
The Four Admin Queues
Project Review Queue
Pending applications. Approve → grant verified badge. Reject → email with reason + 30-day cooldown. All logged in admin_reviews table.
Completion Review Queue
Fraud-engine flagged completions. 4-hour SLA. Approve → sign EIP-712 payout. Reject → blacklist wallet if fraud confirmed.
Withdrawal Review Queue
KYC required above $500 cumulative. Approve → trigger Circle API or Gnosis Safe. Request more docs if KYC incomplete.
Fraud Alert Panel
Velocity alerts, cluster detection. Blacklist wallet cluster or hold entire payout batch for manual sweep.

Verification Engine
Every claim verified independently. Zero trust required.
The verification engine is the core IP. It is a set of BullMQ workers — one per quest type — that independently verify a user's claimed action against the blockchain or social platform API. No human is in the approval loop for standard quests.
1
POST /api/quests/complete → API returns 202 immediately
Never block the HTTP response waiting for verification. Job queued in BullMQ on Upstash Redis. User sees "Verification in progress." No gateway timeout risk. Fan-out to the correct worker type.
2
Worker dispatched based on quest type
BlockchainWorker (deposit/trade): Alchemy getAssetTransfers → match tx by wallet, amount, timestamp, contract. TwitterWorker: GET /2/users/:id/following → is target in list? DiscordWorker: getChatMember(guild, user) → status = member. GitHubWorker: GET /repos/stargazers → username in list?
Concurrent workers · independent scaling
3
Multi-layer fraud checks run in sequence
1) Sybil score ≥ quest minimum? 2) Funder cluster: 3+ wallets from same source → flag cluster. 3) Velocity limit: max 5 per hour per wallet via Redis INCR. 4) Idempotency: UNIQUE(evidence_tx_hash) — same tx never verified twice.
Any check fails
Mark FAILED
User notified with specific reason. Wallet logged. Fraud flags stored in JSONB on completion record. No USDC moves.
All checks pass
Schedule hold → Payout
Social quests: BullMQ delayed job at T+72h. On-chain quests: 30-min hold. Re-verify then EIP-712 sign and release().

Crypto: enter any EVM wallet address. Circle API sends USDC on-chain. Tx confirmed in 1–3 minutes. Tx hash delivered. Done. Fiat: KYC check runs first — if already verified, go straight to provider selection.

Why this matters competitively
Galxe and Layer3 pay in project tokens that users immediately dump. Web3Cash pays USDC and gives users a path to spend it as real money. A user who converted their earnings to fiat cash is a retained, real user — not a farm wallet.
